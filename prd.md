Technical Stack & Development Principles2.1 Technology Stack & ArchitectureFramework: Next.js (App Router, Turbopack)  Runtime: Node.js (>= 22.0.0 LTS)  Package Manager: pnpm (>= 11.0.0)  Language: TypeScriptDatabase & ORM: PostgreSQL with Prisma ORM  Media Processing: Sharp (sharp) for image optimization, cropping, WebP conversion, and upload handling  Canvas Engine: Konva (react-konva) for interactive template customization  Deployment & CI/CD: Hostinger VPS (Linux) & GitHub Actions (Node 22 validation)  2.2 Core Development Principles for Agents & DevelopersPreserve Existing Functionality: Do NOT remove working routes, API endpoints, or UI features unless explicitly instructed.  Do NOT remove Beranda or the /dashboard route.  Do NOT rename the brand from DC Wedding.  Do NOT replace existing implementations with fake/mock data.  Single Source of Truth (Database First): Shared data (such as couple names, event dates, and user profiles) MUST be saved to and read from the database. Do not rely on ephemeral browser cookies, localStorage, or duplicate forms.  Centralized Access Control: Authorization MUST be checked server-side. UI gates should reflect central server entitlements (hasPaidDigitalInvitation, hasGuestbook, etc.).  Extend Over Replace: Inspect current codebase/API/schema before adding new code. Extend existing patterns.  3. Design System & UI/UX Standards3.1 Typography HierarchyCinzel: Primary display, headings, titles, branding, and elegant editorial elements.  Fauna One: Primary body/UI font for readable paragraphs, navigation, forms, buttons, and general application text.  DM Mono: Utility & technical typography (metadata, QR identifiers, timestamps, status badges, uppercase labels).  3.2 Visual ThemesLight Theme (Default): Maroon / Burgundy / Deep Wine accents on a Creamy / Ivory / Warm Neutral background. Body text uses high-contrast black or dark brown on light surfaces.  Dark Theme: Black / Near-Black background with Pink / Soft Rose primary accents and clean White / Light Neutral body text.  3.3 Layout, Spacing & Readability RulesAnti-Blur & High Contrast: All text, UI menus, and button labels MUST use bold/semi-bold weights (font-medium / font-semibold) with high-contrast colors. Never use washed-out/muted grays that hinder readability.  Icon Sizing & Touch Targets: Icons MUST NOT be overly tiny. Standardize icons to at least w-5 h-5 or w-6 h-6 for primary menu items and actions. Ensure interactive elements have a minimum clickable area of 44x44px.  Generous Spacing: Utilize available screen space effectively (p-4, p-6, gap-4). Avoid cramming components together.  4. 7. Detailed Feature Specifications & Modules7.1 Dashboard Structure & NavigationGlobal Navbar: User greeting, Transactions, Package & Add-on upgrades, FAQ, Help, and Logout.  Main Navigation Menu:Beranda: Dashboard overview, invitation stats, RSVP metrics, and quota display.  Rangkaian Acara: Centralized editor for event date, time, venue, address, and Google Maps URL.  Undangan Digital: Workspace for managing both WEDDING and ADAT_AKAD invitations.  Galeri & Foto / Musik Undangan: Custom asset upload management.  RSVP: Analytics, guest response list, and QR ticket issuance.  Manajemen Tamu: Guest database, session scheduling, table & seat assignments.  Guest Book: Onsite check-in logs and terminal status (Guest Book package required).  Usher App: QR scanner and search portal for event staff.  7.2 Digital Invitation Management & Subdomain RoutingSubdomain Architecture:Main Wedding Invitation: https://[nama-pasangan].dcwedding.com  Special Event Invitation (Akad/Sangjit): https://[nama-pasangan][.dcwedding.com/event-khusus](https://.dcwedding.com/event-khusus)  Dual-Card Workspace (InvitationManagementPanel):Separate cards for Main Wedding and Special Event.  Actions per card: Copy Link, Preview (opens tab), Edit Design (deep-links directly to Studio with correct type query ?type=ADAT_AKAD), and Publish/Unpublish toggle.  Password Protection Gate:Allows setting a universal invitation password.  Passwords are hashed (bcrypt) and validated via server-side endpoints with signed access cookies.  Hashed secrets are sanitized and never exposed in client API responses.  7.3 Studio Editor & Asset EngineAsset Upload Validation:Custom photos: Maximum 30 photos per invitation (Max file size: 15 MB, processed via Sharp to WebP).  Custom audio: Maximum 1 active background music track per invitation (Max file size: 10 MB).  Deep Linking: Studio reads ?type=ADAT_AKAD to switch between main wedding and special event templates effortlessly.  7.4 RSVP Module & AnalyticsMetric Cards:Total RSVP Responses  Total Confirmed Attending  Total Accumulative Guests (Pax)  Total Checked-In Guests  Guests Giving Digital Angpao  Guests Giving Physical Gifts  Controls & Features: Real-time search, sorting, CSV/Excel export, manual check-in override, and QR ticket preview modal.  7.5 Guest Management, Tables & SeatsEntitlement: Included in Digital Invitation package.  Data Fields: Guest Name, Phone, Pax Count, RSVP Status, Session, Table Assignment, Seat Assignment, and QR Ticket Status.  Table Constraint: UI prevents assigning more guests/seats than the configured table capacity.  7.6 Onsite Check-in & Usher AppEntitlement: Guest Book package exclusive.  Architecture: Server-authoritative check-in system.  Validation Flow:PlaintextScan QR / Search Name ──► Server Lookup ──► Verify Validity & Duplicate Status ──► Record `checkedInAt` & `checkedInBy` ──► Return Table & Seat Info
Duplicate Protection: Re-scanning an already checked-in QR immediately triggers an explicit alert ("Already checked in") to prevent duplicate entry.  8. Definitions of Done (DoD)Invitation Publication DoD:Onboarding completed ──> Subdomain generated ──> Event details set in Rangkaian Acara ──> Template edited in Studio ──> Publish toggled ──> Guest opens [namapasangan].dcwedding.com (passgate prompts if enabled).  RSVP & QR DoD:Guest submits RSVP form on invitation site ──> Server persists entry ──> Unique opaque QR token issued ──> Confirmation page displays ticket + Google Calendar link ──> Dashboard RSVP metrics update in real-time.  Usher Check-in DoD:Staff scans QR via Usher App ──> Server validates token ──> System updates check-in timestamp atomically ──> Screen shows assigned table and seat number ──> Subsequent scan shows duplicate error.
