Technical Stack, Dependencies & Principles2.1 Core Technical StackFramework: Next.js App Router / Turbopack  Runtime & Package Manager: Node.js >= 22 LTS | pnpm >= 11  Language: TypeScript  UI & Styling: Tailwind CSS v4 + Shadcn UI + tw-animate-css  Animation Engine: Motion via motion/react  Database & ORM: PostgreSQL + Prisma  Media & Canvas: Sharp (image processing) | Konva / react-konva (interactive seating 2D)  Deployment & CI/CD: Hostinger VPS + GitHub Actions  2.2 Core Key Dependencies@radix-ui/react-slot & class-variance-authority (CVA)  lucide-react (System Iconography)  2.3 System Architecture PrinciplesExtend Over Replace: Pertahankan route, API, UI, dan data flow yang sudah berjalan. Halaman /dashboard dan Beranda (/) wajib dipertahankan.  Brand Realignment: Semua antarmuka publik dan internal wajib menggunakan label DC Organizer (menggantikan nama lama DC Wedding).  Single Source of Truth: Database PostgreSQL adalah single source of truth. Undangan baru harus dimulai dari kondisi kosong (clean slate, tanpa data sampel/palsu).  Server-Authoritative: Otorisasi, limitasi, serta validasi kuota/kapasitas dikontrol sepenuhnya di server-side. UI gate mencerminkan entitlement server secara akurat.  3. Data Architecture, Auth & Routing5.1 Onboarding & Registration AlurSimplified Manual Register: Form pendaftaran awal (RegisterDialog) hanya meminta email, password, konfirmasi password, dan persetujuan Terms/Privacy. Field Nama Depan dan Nama Belakang dihapus dari dialog pendaftaran untuk mengurangi gesekan.  Onboarding Data Collection: Data groomName, brideName, dan firstName dikumpulkan secara terpisah pada alur onboarding dashboard.  Prisma User & Wedding Model: firstName disimpan pada User.firstName, sekaligus membuat record WEDDING dan EVENT_KHUSUS. Nama pasangan ter-lock (read-only) pada editor event khusus turunan.  5.2 Routing & URL StructureMain Wedding URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)  Event Khusus URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)[nama-event]  Proxy Routing (proxy.ts): Mengani tenant/event routing secara otomatis ke /invite/[slug]/[eventSlug]. Alias /event-khusus dan /invite/[slug] dipertahankan untuk backward compatibility.  Universal Password Protection: Proteksi kata sandi undangan menggunakan bcrypt hash & cookie akses yang berlaku universal di root maupun sub-event path.  6. Detailed Feature Specifications & API Enforcements6.1 Interactive Seating Builder (Konva 2D Engine)Visual Engine: Berbasis 2D Konva (react-konva).  Database Constraints: Schema Guest.seatNumber Int? dengan aturan @@unique([tableId, seatNumber]).  Server Limits (POST /api/tables):Jumlah meja: 1 – 100 meja per undangan.  Jumlah kursi: 1 – 50 kursi per meja.  Bentuk meja (Shape): Terbatas pada ROUND, RECTANGLE, atau SQUARE.  Drag & Drop & Atomic Swap:Drop ke kursi kosong $\rightarrow$ PATCH /api/guests/[id].  Drop ke kursi terisi $\rightarrow$ Konfirmasi Swap $\rightarrow$ Atomic Swap via POST /api/guests/[id]/swap dalam transaksi Prisma.  Seating Roster Eligibility Enforcement (PATCH /api/guests/[id] & /swap):Roster seating dan mutasi API hanya menerima tamu berkategori MANUAL atau tamu RSVP yang berstatus ATTENDING.  Tamu RSVP dengan status DECLINED / PENDING ditolak oleh server jika dimasukkan ke denah.  Pengecekan kapasitas meja dan kursi ganda hanya menghitung kualifikasi eligible roster.  6.2 Guest Management API Validation (POST /api/guests)Relasi Meja & Undangan: Memvalidasi bahwa tableId milik undangan yang sedang aktif.  Kapasitas Meja: Meja yang sudah penuh mengembalikan response HTTP 409 Conflict.  Plus Ones Validation: Atribut plusOnes wajib berupa non-negative integer.  Unassigned Guest Support: Tamu tetap dapat dibuat tanpa alokasi meja awal (tableId = null).  6.3 Bilingual UI Foundation (ID / EN)Lightweight Locale Layer: Dukungan bahasa tanpa dependensi pihak ketiga, terbatas pada id (Bahasa Indonesia) dan en (English).  Persistence & Hydration: Bahasa tersimpan pada cookie dc_locale dan diinisialisasi secara server-side pada root layout (<html lang="...">).  Components: Dikelola via LanguageProvider dan LanguageToggle (tombol bersih ID / EN di navbar tanpa ikon ambigu).  7. Extended Workspace & Landing Specifications7.1 Digital Invitation Workspace (/dashboard/undangan-digital)Layout & Palette: Batas lebar w-[min(92vw,1400px)]. Kanvas bersifat netral dengan semantic borders tipis.  Action Hierarchy: Primary action menggunakan GlowButton ringkas (tinggi ~40px).  Responsive Overflow Protection: Dilengkapi min-w-0, break-all, dan overflow-x-clip pada blok URL publik agar URL panjang tidak memicu horizontal scrollbar.  7.2 Digital Invitation Landing (/d-invitation)Realistic Phone Mockup: Hero section menampilkan preview undangan interaktif di dalam smartphone frame realistis (dengan outer shell, tombol samping, bezel, dan Dynamic Island cutout).  Package Integration: Menampilkan paket resmi (GUESTBOOK_DIGITAL & DIGITAL_INVITATION) dalam grid simetris dengan batas max-w-4xl.  Showcase CTA: Menggunakan GlowButton via asChild agar selaras dengan tombol utama landing.  Local Preview Assets: Galeri template menggunakan aset lokal resmi dari folder /public (hp-digital.png, bca.webp, wo.png).  8. Definition of Done (DoD)Dashboard & Studio: Tombol Edit Design mengarahkan ke Studio dengan query ?type=, dan tombol Back mengembalikan pengguna ke /dashboard/undangan-digital.  Seating Builder: Penempatan kursi kosong tersimpan ke database; penempatan pada kursi terisi mewajibkan konfirmasi Swap yang bersifat atomic.  Seating Roster Enforcement: Tamu non-ATTENDING RSVP secara otomatis ditolak oleh server saat dimasukkan ke denah.  Button System Uniformity: Seluruh tombol di aplikasi merender primitive GlowButton dan menggunakan hirarki size.  Brand Consistency: Tidak ada lagi penggunaan label DC Wedding pada antarmuka publik maupun internal (semua menggunakan DC Organizer).  No Layout Shifts: Seluruh halaman publik dan dashboard aman dari isu teks terpotong (clipped) atau overflow horizontal di layar kecil.
