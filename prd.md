Product Definition & VisionDC Organizer adalah platform SaaS pernikahan yang berpusat pada Undangan Pernikahan Digital (Digital Wedding Invitation) dan alur kerja manajemen tamu real-time.  Core Lifecycle:Wedding Setup → Invitation Creation → Publication → Distribution & Guest Roster → RSVP & Gift Tracking → Guest Management & Seating → QR Ticket → Wedding-Day Check-in → Usher App / Onsite Guest Book.  Positioning: DC Organizer bukan sekadar generator undangan digital biasa, melainkan platform manajemen tamu pernikahan digital end-to-end dengan Undangan Digital sebagai pintu utamanya.  2. Technical Stack, Architecture & Principles2.1 Technical StackFramework: Next.js App Router / Turbopack  Runtime: Node.js >= 22 LTS  Package Manager: pnpm >= 11  Language: TypeScript  UI & Styling: Tailwind CSS v4 + Shadcn UI  Animation Engine: Motion via motion/react  Code Quality & Tooling: Prettier (Tailwind plugin) + ESLint  Database & ORM: PostgreSQL + Prisma  Media Engine: Sharp (image processing & cropping)  Canvas Engine: Konva / react-konva (interactive seating & visual editor)  Deployment & CI/CD: Hostinger VPS + GitHub Actions  2.2 Key Dependencies & Primitive Libraries@radix-ui/react-slot & class-variance-authority (CVA)  lucide-react (System Iconography)  2.3 Core Principles & Architecture GuidelinesExtend Over Replace: Pertahankan route, API, UI, dan alur data yang sudah berfungsi kecuali diperintahkan sebaliknya. Halaman /dashboard dan Beranda (/) harus tetap ada.  Brand Realignment: Semua UI publik & internal harus menggunakan nama DC Organizer (menggantikan label lama DC Wedding).  Single Source of Truth: Database adalah single source of truth. Undangan baru harus dimulai dari kondisi kosong (tanpa data default / palsu).  Server-Authoritative: Otorisasi dan validasi kuota/kapasitas bersifat server-side; UI gate mencerminkan entitlement server secara tepat.  3. Semua reusable application buttons wajib dirender melalui Button.  Visual Variant: Hanya satu visual treatment. Tidak ada perbedaan visual antar variant; legacy variant names hanya dipertahankan untuk source compatibility.  Size Language: size menjadi satu-satunya sumbu styling dan digunakan untuk hierarchy: xs, sm, default, lg, icon-xs, icon-sm, icon, dan icon-lg.  Compatibility: components/ui/button.tsx adalah canonical primitive sekaligus compatibility surface untuk import Button/buttonVariants lama. Kode baru wajib mengimpor Button langsung dan tidak boleh membuat primitive button visual kedua.  Behavior: Button menyediakan focus, hover, active, disabled, click feedback, dan icon treatment secara terpusat. Legacy variant names tidak menghasilkan visual treatment berbeda.  3.4 Motion, Layout & Background ContinuityMotion: Menggunakan motion/react dengan prinsip pergerakan yang halus (animasi transform/opacity) serta mendukung useReducedMotion() untuk aksesibilitas.  Pintu Navigation: Halaman Landing menggunakan fitur Pintu sebagai permukaan navigasi interaktif 3D untuk 3 workspace: Wedding Planner, Digital Invitation, dan Guestbook.  Protected Background Elements: Efek Rose Petals pada components/Layout/background.tsx adalah elemen visual sakral yang dilindungi (jumlah, animasi, waktu, dan bayangan tidak boleh diubah).  Navbar Canvas Continuity: Kontrol navbar publik menggunakan opasitas yang terkontrol dan membagikan keluarga kontrol 44px (h-11). Header publik bersifat transparan/kONTINU dengan kanvas bg-transparent, dan ambient decorative glow dibatasi mulai dari bawah zona navbar (top-24) agar tidak membentuk garis warna kontras yang memotong header.  Content Width Standardization: Lebar konten publik (Navbar, Landing, /d-invitation, dan Workspace Shell) disatukan menggunakan batas w-[min(92vw,1400px)].  4. Arsitektur Data, Autentikasi & URL Publik5.1 Onboarding & Registration AlurSimplified Manual Register: Pendaftaran manual via RegisterDialog hanya meminta email, password, konfirmasi password, serta persetujuan Terms/Privacy. Nama Depan dan Nama Belakang dihapus dari form pendaftaran awal untuk mengurangi gesekan.  Onboarding Data Collection: Data groomName, brideName, dan firstName dikumpulkan secara terpisah pada alur onboarding dashboard.  Prisma User & Wedding Model: firstName disimpan pada User.firstName, sekaligus membuat record WEDDING dan EVENT_KHUSUS. Nama pasangan di-lock (read-only) pada editor event khusus turunan.  5.2 Routing & URL PublikMain Wedding URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)  Event Khusus URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)[nama-event]  Proxy Routing (proxy.ts): Mengani tenant/event routing secara otomatis ke /invite/[slug]/[eventSlug]. Alias /event-khusus dan /invite/[slug] dipertahankan untuk backward compatibility.  Universal Password Protection: Proteksi kata sandi undangan menggunakan bcrypt hash & cookie akses yang berlaku universal di root maupun sub-event path.  6. Spesifikasi Fitur Utama & API Rules6.1 Interactive Seating Builder (Konva 2D Engine)Visual Engine: Berbasis 2D Konva (react-konva).  Database Constraints: Schema Guest.seatNumber Int? dengan aturan @@unique([tableId, seatNumber]).  Server Enforcements & Limits (POST /api/tables):Jumlah meja: 1 – 100 meja per undangan.  Jumlah kursi: 1 – 50 kursi per meja.  Bentuk meja (Shape): Terbatas pada ROUND, RECTANGLE, atau SQUARE.  Drag & Drop & Atomic Swap:Drop ke kursi kosong → PATCH /api/guests/[id].  Drop ke kursi terisi → Pop-up konfirmasi Tukar Posisi (Swap).  Penukaran posisi kursi berjalan secara atomic via POST /api/guests/[id]/swap di dalam transaksi Prisma.  Seating Roster Eligibility Enforcement:Roster tamu seating dan mutasi API (PATCH & /swap) hanya menerima tamu berkategori MANUAL atau tamu RSVP yang berstatus ATTENDING.  Tamu RSVP dengan status DECLINED / PENDING ditolak oleh server jika dimasukkan ke denah.  Pengecekan kapasitas meja dan kursi ganda hanya menghitung kualifikasi eligible roster.  6.2 Guest Management & Validasi API (POST /api/guests)Relasi Meja & Undangan: Memvalidasi bahwa tableId milik undangan yang sedang aktif.  Kapasitas Meja: Meja yang sudah penuh akan mengembalikan respon HTTP 409 Conflict.  Plus Ones Validation: Atribut plusOnes harus berupa non-negative integer.  Flexibility: Tamu tetap bisa dibuat tanpa harus langsung dialokasikan ke meja (unassigned guest).  6.3 Fondasi Internasionalisasi (Bilingual UI ID/EN)Lightweight Locale Layer: Dukungan bahasa bawaan tanpa dependensi pihak ketiga, terbatas pada id (Bahasa Indonesia) dan en (English).  Persistence & Hydration: Bahasa tersimpan di cookie dc_locale dan diinisialisasi secara server-side pada root layout (<html lang="...">).  Components: Diatur melalui LanguageProvider dan LanguageToggle (tombol bersih ID / EN di navbar).  Copywriting Standards: Teks tidak diterjemahkan secara harfiah (literal translation), melainkan disesuaikan dengan narasi produk romantis dan profesional.  7. Extended Workspace & Landing Features7.1 Digital Invitation Workspace Redesign (/dashboard/undangan-digital)Layout & Palette: Menggunakan konsep editorial workspace dengan batas lebar w-[min(92vw,1400px)]. Kanvas bersifat netral, minim surface fill, serta menonjolkan batas garis tipis (semantic borders).  Action Hierarchy:Primary Action: Tombol Rose #C07A84 ringkas (tinggi ~40px) dengan subtle depth.  Secondary / Utility Actions: Menggunakan canonical Button dengan ukuran lebih kecil untuk hierarchy; visual treatment tetap identik.  Responsive Overflow Protection: Dilengkapi dengan min-w-0, break-all, dan overflow-x-clip pada blok URL publik agar teks URL yang panjang tidak memicu horizontal scrollbar.  7.2 Digital Invitation Landing (/d-invitation)Package Integration: Menampilkan pilihan paket resmi (GUESTBOOK_DIGITAL & DIGITAL_INVITATION) dalam grid simetris dengan batas max-w-4xl.  Showcase CTA: Menggunakan canonical Button via asChild agar selaras dengan tombol utama landing.  Local Preview Assets: Galeri template menggunakan aset lokal resmi dari folder /public (hp-digital.png, bca.webp, wo.png).  8. Definition of Done (DoD)Dashboard & Studio: Tombol Edit Design mengarahkan ke Studio dengan query ?type=, dan tombol Back mengembalikan pengguna ke /dashboard/undangan-digital.  Seating Builder: Penempatan kursi kosong tersimpan ke database; penempatan pada kursi terisi mewajibkan konfirmasi Swap yang bersifat atomic.  Seating Roster Enforcement: Tamu non-ATTENDING RSVP secara otomatis tertolak di server saat hendak ditempatkan pada kursi.  RSVP & Tamu: Filter, pencarian, dan sorting data berjalan instant tanpa full page reload.  Brand Consistency: Tidak ada lagi penggunaan kata DC Wedding pada antarmuka publik/internal.  No Layout Shifts: Seluruh halaman publik dan dashboard aman dari isu teks terpotong (clipped) atau overflow horizontal di layar kecil.  Dokumentasi Material: Setiap pembaruan material tercatat secara berkala tanpa menghapus riwayat historis.
