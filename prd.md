Technical Stack, Architecture & System Principles2.1 Core Technical StackFramework: Next.js App Router / Turbopack  Runtime & Package Manager: Node.js >= 22 LTS | pnpm >= 11  Language: TypeScript  UI & Styling: Tailwind CSS v4 + Shadcn UI + tw-animate-css  Animation Engine: Motion via motion/react  Database & ORM: PostgreSQL + Prisma  Media & Canvas: Sharp (image processing) | Konva / react-konva (interactive seating 2D)  Deployment & CI/CD: Hostinger VPS + GitHub Actions  2.2 Core Key Dependencies@radix-ui/react-slot & class-variance-authority (CVA)  lucide-react (System Iconography)  2.3 System Architecture PrinciplesExtend Over Replace: Pertahankan route, API, UI, dan data flow yang sudah berjalan. Halaman /dashboard dan Beranda (/) wajib dipertahankan.  Brand Realignment: Semua antarmuka publik dan internal wajib menggunakan label DC Organizer (menggantikan nama lama DC Wedding).  Single Source of Truth: Database PostgreSQL adalah single source of truth. Undangan baru harus dimulai dari kondisi kosong (clean slate, tanpa data sampel/palsu).  Server-Authoritative: Otorisasi, limitasi, serta validasi kuota/kapasitas dikontrol sepenuhnya di server-side. UI gate mencerminkan entitlement server secara akurat.  Single Source Theme System: app/globals.css adalah single source of truth untuk seluruh styling dan token tema aplikasi. Seluruh impor CSS tambahan (seperti dashboard-theme.css, brand-theme.css, design-overrides.css) telah dihapus dan dikonsolidasikan.  3. Data Architecture, Auth & Role-Based Routing5.1 Onboarding & Registration FlowSimplified Registration: Form pendaftaran awal (RegisterDialog) hanya memerlukan email, password, konfirmasi password, dan persetujuan Terms/Privacy.  Dashboard Onboarding: Pengumpulan data groomName, brideName, dan firstName dilakukan pada alur onboarding dashboard.  Prisma User & Wedding Link: firstName disimpan pada User.firstName, sekaligus membuat record WEDDING dan EVENT_KHUSUS. Nama pasangan dikunci (read-only) pada editor sub-event.  5.2 Routing & URL StructureMain Wedding URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)  Event Khusus URL: https://[nama-pasangan][.dcwedding.com/](https://.dcwedding.com/)[nama-event]  Proxy Routing (proxy.ts): Mengarahkan tenant/event routing secara otomatis ke /invite/[slug]/[eventSlug].  Universal Password Protection: Proteksi password undangan menggunakan bcrypt hash & cookie akses universal.  5.3 Role-Based Access Control (RBAC) & Dashboard RoutingAplikasi memisahkan hak akses dan pengarahan otomatis route /dashboard berdasarkan Role pengguna:                       ┌──► OWNER    ──► /owner    (User Management, Audit Logs, Multi-role)
                     ├──► ADMIN    ──► /admin    (Operations, Custom Invoices, Manual Verification)
┌─────────────────┐  ├──► FINANCE  ──► /admin    (Payment Verification & Financial Reports)
│ Login / Session │ ─┼──► DESIGNER ──► /designer (Template Catalog Upload & Sales Tracker)
└─────────────────┘  ├──► EDITOR   ──► /designer (Legacy Designer Routing)
                     └──► USER     ──► /dashboard (Wedding Organizer Workspace)
Owner (/owner): Mengelola seluruh akun, mengubah role, serta melakukan reset password akun dengan skema konfirmasi email token sekali pakai (OWNER_CONFIRMATION_EMAIL).  Admin / Finance (/admin): Memverifikasi pembayaran manual, menerbitkan invoice CUSTOM_DESIGN, membantu mengubah nama pengantin/status publish, dan memantau operasional.  Designer (/designer): Mengunggah template baru (preview gambar maks 5 MB, paket ZIP/HTML/JSON maks 25 MB di public/uploads/templates/<templateNo>/), mengelola tag, serta memantau statistik penggunaan/penjualan (salesCount berdasarkan pembayaran PAID).  User (/dashboard): Workspace utama pengantin/WO untuk mengelola acara, undangan digital, RSVP, dan denah tempat duduk.  6. Detailed Feature Specifications & API Enforcements6.1 Interactive Seating Builder (Konva 2D Engine)Visual Engine: Berbasis 2D Konva (react-konva) menggunakan warna kanvas netral dan aksen Rose.  Database Constraints: Guest.seatNumber Int? dengan aturan @@unique([tableId, seatNumber]).  Server Limits (POST /api/tables):Jumlah meja: 1 – 100 meja per undangan.  Jumlah kursi: 1 – 50 kursi per meja.  Bentuk meja (Shape): ROUND, RECTANGLE, atau SQUARE.  Drag & Drop & Atomic Swap:Penempatan ke kursi kosong $\rightarrow$ PATCH /api/guests/[id].  Penempatan ke kursi terisi $\rightarrow$ Konfirmasi Swap $\rightarrow$ POST /api/guests/[id]/swap (Transaksi atomic Prisma).  Seating Roster Eligibility Enforcement: Roster seating dan mutasi API hanya menerima tamu berkategori MANUAL atau tamu RSVP berstatus ATTENDING. Tamu dengan status DECLINED / PENDING ditolak otomatis oleh server jika dimasukkan ke denah.  6.2 Guest Management & RSVP API Validation (POST /api/guests)Relasi & Capacity: Memvalidasi tableId milik undangan aktif. Meja penuh mengembalikan HTTP 409 Conflict.  Data Fields: Atribut plusOnes wajib non-negative integer. Mendukung tamu tanpa alokasi meja (tableId = null).  CSV Export: Ekspor CSV RSVP menggunakan nama file dc-organizer-rsvp.csv dan memuat data: Nama, Telepon, RSVP, Pax, Check-in, Meja.  6.3 Bilingual UI Foundation (ID / EN)Lightweight Locale Layer: Didukung secara internal untuk id (Bahasa Indonesia) dan en (English).  Persistence & Hydration: Disimpan di cookie dc_locale dan diinisialisasi secara server-side pada <html lang="...">.  Navbar Toggle: Menggunakan LanguageToggle tanpa border luar tambahan, dengan active state rose transparan yang konsisten di light maupun dark mode.  7. Workspace, Studio & Public Invitation Specifications7.1 Dashboard Editorial Workspace (/dashboard)Density Pass & Layout: Menghapus deskripsi paragraf berulang dan repeated filled cards. Digantikan oleh statistik berbasis neutral cards dengan border Rose tipis (radius: 12px) dan tabel separate rounded rows (radius: 10px).  Form Controls: Seluruh input, textarea, dan select menggunakan height minimal 44px, radius 10px, background netral tipis, serta focus ring Rose.  Access Notices: Fitur yang terkunci atau memerlukan upgrade (seperti /dashboard/usher) menggunakan komponen terpadu DashboardAccessNotice.  7.2 Invitation Studio WorkspaceType Tabs: Tab opsi jenis undangan (WEDDING / ADAT_AKAD) diset menggunakan fit-content agar tidak membentang/stretch.  Header Action Hierarchy: Controls disusun secara proporsional: Undo/Redo (utility icon), Preview (secondary action), dan Simpan (primary action dengan raised shadow).  7.3 Public Invitation RenderersFigma Classic Template: Mendukung renderer figma-classic dengan layout satu kolom, bingkai stone, hero foto bentuk arch, divider ornamen, event cards, RSVP, dan Gift bank.  Dynamic Template Integration: Template dipanggil secara dinamis dari database (GET /api/templates) berdasarkan ketersediaan DesignerTemplate yang telah di-publish.  Brand Footer: Seluruh renderer publik mewajibkan penggunaan footer bertuliskan DC Organizer.  8. Definition of Done (DoD)Dashboard & Navigation: Tombol Edit Design mengarahkan ke Studio dengan query ?type=, dan tombol Back mengembalikan pengguna ke /dashboard/undangan-digital.  Role & Authorization Shell: Akses /owner, /admin, dan /designer terisolasi sesuai role pengguna dengan tampilan visual yang selaras pada shell dc-dashboard.  Seating Builder & Roster: Penempatan ke kursi terisi menjalankan atomic swap. Tamu non-ATTENDING ditolak server jika dimasukkan ke denah.  Button & Form System Uniformity: Seluruh action button merender primitive Button canonical. Form controls mematuhi standar height minimal 44px dan radius 10px.  Brand Consistency: Tidak ada lagi penggunaan label DC Wedding pada seluruh antarmuka publik, dashboard, invoice, maupun footer (semua menggunakan DC Organizer).  Layout & Overflow Protection: Seluruh area dashboard menggunakan Wide Workspace, aman dari isu teks terpotong (clipped), serta bebas overflow horizontal di layar kecil.
